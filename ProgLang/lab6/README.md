*Рассмотрим следующую программу на С++.*
```
#include <iostream>
```

*Проверьте четыре способа объявления* **Pi**.
* ```const auto Pi = acos(0) * 2;```
* ```constexpr auto Pi = std::acos(0) * 2;```
* ```const auto Pi = acos(x) * 2;```
* ```constexpr auto Pi = std::acos(x) * 2;```

*Что можно сказать об этих вариантах? Проверьте, в каких вариантах объявляется константа этапа трасляции.*

*Тексты программ разместите в папке с номером задания*

* const запрещает изменение значения переменной после её инициализации, но оно не требует, чтобы значение было вычислено во время компиляции. constexpr требует, чтобы переменная была инициализирована константным выражением, которое допускает вычисление на этапе трансляции. auto позволяет компилятору автоматически определить тип переменной по начальному значению. В первых трех вариантах выводиться число 3.14159, а в 4 варианте выводиться ошибка.
* В первом варианте используется выражение acos(0) * 2. Программа компилируется, а переменная Pi получает значение, приближённое к числу pi. Однако const не заставляет пк считать формулу заранее.
* Во втором варианте применяется constexpr. Программа компилируется, здесь объявляется константа этапа трансляции, так как в современных версиях C++ функция std::acos поддерживает вычисление на этапе трансляции и может использоваться в константном выражении.
* В третьем варианте аргументом функции является переменная x. Несмотря на то что она инициализирована нулём, она не объявлена как константа этапа трансляции. Поэтому Pi является обычной константой, значение которой может вычисляться во время выполнения программы.
* В четвёртом варианте делается попытка объявить константу этапа трансляции с помощью constexpr, но выражение содержит обычную переменную x. Это не позволяет вычислить значение во время компиляции, поэтому константа этапа трансляции не создается, а программа завершается ошибкой компиляции(error: the value of 'x' is not usable in a constant expression).
* Таким образом, const и constexpr имеют разное назначение. const запрещает изменение значения переменной, а constexpr дополнительно требует возможности вычислить её значение на этапе трансляции.


### Задание 2 **(2)**
*Проверьте работу следующей программы на С++*
```
#include <iostream>
int main() {
   {
      int x, y;
      std::cin >> x >> y;
      std::cout << x+y << std::endl;
   }
   {
      double x, y;
      std::cin >> x >> y;
      std::cout << x+y << std::endl;
   }
   return 0;
}
```
*Нужны ли в этой программе вложенные фигурные скобки? Дайте подробный ответ с объяснением причин.*

* Фигурные скобки определяют область видимости локальных переменных. Переменные x и y, объявленные в первом блоке, доступны только внутри него. После закрывающей скобки их область видимости заканчивается. Поэтому во втором блоке можно повторно использовать имена x и y, объявив их с типом double.
* Если убрать фигурные скобки у обоих блоков, объявления переменных с одинаковыми именами окажутся в одной области видимости. Это приведёт к ошибке компиляции, так как повторно объявить такие переменные с другими типами в одной области видимости нельзя.
* Таким образом, фигурные скобки в этой программе необходимы для разделения областей видимости переменных. При этом их можно заменить другими способами организации кода, например использовать разные имена переменных. Скобки нужны не для выполнения сложения, а для возможности повторного объявления переменных с одинаковыми именами.

```
for (int i = 0; i < 4; i++) {
```

* В результате значение s равно сумме вкладов обоих циклов: 4 * (0+1+2) + (0+1+2+3) = 18, программа выводит число 18

*Рассмотрим следующий фрагмент программы. Эта программа 1000000 раз обменивает значения двух длинных 
строк с использованием третьей строки. Проверьте, насколько быстро она работает.*

```
std::string a(100000, 'a');

for (int i=0;i<1000000;i++) {

std::cout << a[0] << b[0];
```
*Попробуйте использовать для обмена значений строк функцию* **swap**. 
*Проверьте, изменилось ли время работы. В чем ошибка исходной программы?
Исправьте исходную программу, чтобы ускорить ее работу. Изменения не должны 
затрагивать общий вид программы (присваивания, использование временной переменной).*

* Первый код программы, копирование строк:
```cpp
#include <iostream>
#include <string>
#include <chrono>
using namespace std;

int main() {
    string a(100000, 'a');
    string b(100000, 'b');

    for (int i = 0; i < 1000000; i++) {

        a = b;
        b = c;
    }
    cout << a[0] << b[0] << endl;

}
```
* Вывод программы:
```
ab
Operating hours: 5.6646
```

* Второй код программы, использование swap():
```cpp
#include <iostream>
#include <string>
#include <chrono>
using namespace std;

int main() {
    string a(100000, 'a');
    string b(100000, 'b');
    auto start = chrono::high_resolution_clock::now();

    string c;
    for (int i = 0; i < 1000000; i++) {
        swap(c, a);
        swap(a, b);
        swap(b, c);
    }
    cout << a[0] << b[0] << endl;

    auto end = chrono::high_resolution_clock::now();
    cout << "Operating hours: " << chrono::duration<double>(end - start).count() << endl;
}
```

* Вывод программы:
```
ab
Operating hours: 0.0113294
```

* После замены копирования на swap() программа стала работать значительно быстрее. В первом варианте время составило 5,6646 сек, а во втором 0,0113294 сек. Это связано с тем, что swap() позволяет обменивать содержимое строк без обычного копирования всех символов.
* Ошибка исходной программы заключается в избыточном копировании данных. На каждой итерации создаётся копия строки a, после чего содержимое строк копируется с помощью присваивания. При длине строк 100 000 символов и миллионе итераций это приводит к значительным затратам времени.

* Третий код программы, исправление исходной программы с сохранением общего вида:
```cpp
#include <iostream>
#include <string>
#include <chrono>
#include <utility>
using namespace std;

int main() {
    string a(100000, 'a');
    string b(100000, 'b');
    auto start = chrono::high_resolution_clock::now();

    for (int i = 0; i < 1000000; i++) {
        string c(move(a));
        a = move(b);
        b = move(c);
    }
    cout << a[0] << b[0] << endl;

    auto end = chrono::high_resolution_clock::now();
    cout << "Operating hours: " << chrono::duration<double>(end - start).count() << endl;
}
```
* Вывод программы:
```
ab
Operating hours: 0.0118618
```
* Для ускорения обмена вместо обычного копирования используется move(). Для её применения подключается заголовочный файл <utility>. Сначала string c(move(a)) создаёт временную строку c, передавая ей ресурсы строки a. Затем a = move(b) передаёт строке a ресурсы строки b. Последняя команда b = move(c) передаёт строке b ресурсы временной строки c.
* Таким образом, содержимое строк обменивается без обычного копирования всех символов. После перемещения исходный объект остаётся пригодным для дальнейшего использования, но его содержимое не определено. В данном случае это не мешает работе, поскольку строки затем получают новые значения.
* Использование move() позволило значительно ускорить программу по сравнению с исходным вариантом. При этом сохранились временная переменная и последовательность из трёх операций обмена. Время выполнения уменьшилось с 5,6646 до 0,0118618 секунды.

можно использовать оператор взятия адреса* **&**. *Адрес можно интерпретировать, как 
беззнаковое длинное число с использованием* **reinterpret_cast**.

```
reiterpret_cast<unsigned long long>(&t);
```
*Здесь* **t** *имя некоторой переменной. Напишите несколько примеров, чтобы проверить, 
как размещаются переменные в памяти. В частности, можно рассмотреть следующие вопросы.*
* *Если объявить несколько переменных различных типов в одном блоке, то на какую величину 
отличаются их адреса? Соотносится ли эта величина с размером переменной в байтах.
Проверьте, имеются ли различия на разных уровнях оптимизации.*
* *Если имеется несколько блоков, расположенных последовательно, то могут ли переменные
в разных блоках иметь одинаковые адреса? Проверьте разные уровни оптимизации.*
* *Объявите несколько переменных типа* **std::string** *и попробуйте заносить
в них строки различной длины. Изменяется ли размер переменной, вычисленный с использованием*
**sizeof**? *Изменяется ли расположение переменной? Попробуйте объяснить полученные результаты.*
