*Переведите в двоичную запись два произвольных рациональных числа (числа вида* $\frac{p}{q}$).

от 9 до 12.*

*Запись второго числа будет содержать период. Его надо найти. При решении задачи нельзя

* 13:2 = 6 (ост 1);

* 3:2 = 1 (ост 1);
* 1:2 = 0 (ост 1),
* Значит 13 в десятич = 1101 в двоич. Так как знаменатель 32 = 2^5, двоичная запятая сдвигается на пять разрядов влево: 13/32 = 0,01101 в двоич

* 1/12 × 2 = 1/6, целая часть 0 
* 1/6 × 2 = 1/3, целая часть 0 
* 1/3 × 2 = 2/3, целая часть 0
* 2/3 × 2 = 4/3 = 1 + 1/3, целая часть 1, остаток равен 1/3. 
Остаток 1/3 повторился, поэтому дальнейшие вычисления будут повторяться. После первых двух нулей периодически повторяется последовательность цифр 01, значит 1/12 = 0,00(01) в двоич

### Задание 4 **(2)**

*Рассмотрим следующий пример в IDLE Python*
```
>>> x = 99.99
>>> int(x/10+0.001)
9
```
*Результат должен был быть равен 10, однако оказался другим. Почему так произошло?
Как исправить программу, чтобы она корректно переводила вещественные числа в целые?*

* В Python числа типа float хранятся в двоичном формате. Некоторые десятичные дроби нельзя представить в нём абсолютно точно, поэтому при вычислениях может возникнуть небольшая погрешность. В выражении x / 10 + 0.001 результат может оказаться немного меньше 10. Функция int() отбрасывает дробную часть числа, поэтому вместо 10 получается 9.
* Для исправления программы можно использовать функцию round(), которая округляет число до ближайшего целого:
```py
x = 99.99
print(round(x / 10))
```
* Результат выполнения программы будет 10.
* Причина ошибки заключается в погрешности представления вещественных чисел и в том, что функция int() не округляет число, а отбрасывает его дробную часть.

### Задание 5. **(2)**

*Рассмотрите следующую программу. Объясните результаты ее работы. В частности,
как величина* $y$ *повлияла на ответ?*
```
x = 1/3
y = 1
for i in range(20):
    print((x+y)-y)
    y*=10
```
*В отчете требуется привести вычисления для оценки погрешности.*

* Причина искажения результатов: компьютер хранит вещественные числа с ограниченной точностью (15–17 верных десятичных цифр (формат float64)). При сложении огромного числа y и маленького x = 1/3 разряды x сдвигаются вправо, из-за чего его младшие разряды выходят за пределы доступной памяти и отбрасываются.
* Оценка погрешности:
Абсолютная ошибка округления привязана к большему числу, = 1.11 * 10^(-16) * y
Относительная ошибка показывает долю искажения от правильного ответа, = (1.11 * 10^(-16) * y) / (1/3) = 3.33 * 10^(-16) * y
Получается относительная погрешность растет прямо пропорционально росту y, постепенно уничтожая верные цифры в ответе
* Влияние величины y: 
При y = 10^15: из-за нехватки памяти разрядов памяти компьютер выдает значение 0.375(3/8) вместо истинного 1/3. Абсолютная погрешность результата составляет 1/24 а относительная погрешность равна 1/8
При y >= 10^16: число y становится настолько гигантским, что компьютер просто перестает «видеть» прибавку x. Выражение (x + y) округляется обратно до y, а финальная разность y - y дает ровно 0.0.


### Задание 6 **(2)**

*Для какого минимального значения* $n$ *программа на С++ выведет* **inf**? *Объясните
ответ.* *Что произойдет, если тип* **double** *заменить на* **long double**?
```
int n=...;
double s = pow(2, n);
std::cout << std::fixed << s << std::endl;
```

* Тип double в C++ выделяет под порядок числа 11 бит, из-за этого имеет строгое ограничение по максимальному значению: примерно 1.79 * 10^308. В двоичной системе этот предел равен 2^1024, но самым большим числом, которое пк ещё способен сохранить, является 2^1023. 
При n = 1023 число 2^1023 еще укладывается в доступный диапазон double. При n = 1024 значение 2^1024 достигает критического порога. Происходит переполнение, и компьютер вместо числа выдает inf. Значит минимальное значение n = 1024
* При замене double на long double тип long double включает расширенный режим процессора и занимает 80бит. Под хранение порядка числа выделяется больше места, поэтому лимит сдвигается до 2^16384. В этом случае переполнение и inf мы увидим только при n = 16384.

### Задание 8 **(2)**

*Какое минимальное натуральное число при преобразовании в тип* **double** *записывается с погрешностью? Объясните
ответ. Почему следующее за ним число уже выводится без погрешности?*

* В типе double под значащую часть числа выделено ровно 53 двоичных бита. Это значит, что любое целое число вплоть до 2^53(9007199254740992) пк помнит идеально точно.
* 9007199254740993 идет с погрешностью, потому что это число на единицу больше лимита (2^53 + 1). Чтобы записать его в двоичном виде, пк не хватает 53 бита. В итоге лишняя единица отбрасывается, число округляется обратно до 9007199254740992, и мы получаем ошибку округления.
* 9007199254740994 выводится без погрешности, потому что после отметки 2^53 компьютер физически не может видеть разницу в одну единицу. Шаг между числами, которые он способен различать в этой зоне, становится равен 2. Число 9007199254740994 это как раз 2^53 + 2. Оно четное и идеально попадает в эту новую разрядность пк, поэтому сохраняется и выводится без искажений.
