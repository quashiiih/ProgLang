### Задание 2 **(3)**
*Напишите пример программы на С++ с использованием целочисленных литералов в разных форматах записи, 
разной длины, знаковых и беззнаковых. 
Пример должен охватывать большинство способов записи целочисленных литералов.*

```cpp
#include <iostream>
using namespace std;

int main() {
    // 1. Форматы записи (разные системы счисления для числа 123)
    int dec = 123;          // Десятичная система (без префикса)
    int oct = 0173;         // Восьмеричная система (префикс 0)
    int hex = 0x7B;         // Шестнадцатеричная система (префикс 0x)
    int bin = 0b01111011;   // Двоичная система (префикс 0b)

    // 2. Использование суффиксов длины и знаковости (тип определяется литералом)
    auto a = 321;            // знаковый int
    auto b = 321L;           // Знаковый long (суффикс L)
    auto c = 321LL;          // Знаковый long long (суффикс LL)
    auto d = 321U;           // Беззнаковый int (суффикс U)
    auto e = 321UL;          // Беззнаковый long (суффикс UL)
    auto f = 321ULL;         // Беззнаковый long long (суффикс ULL)

    // Вывод результатов
    cout << dec << " " << oct << " " << hex << " " << bin << endl;
    cout << a << " " << b << " " << c << endl;
    cout << d << " " << e << " " << f << endl;
    return 0;
}
```

*Почему ее вывод отличается от вывода программы на С++?*

* Программа на Python
```py
a = 'a'
a = chr(ord(a) + 10) 
print(a, end='')

a = chr(ord(a) + 250) 
print(a, end='')
```

* вывод: kť
* Функция ord() возвращает числовой код символа, а функция chr() возвращает символ по его числовому коду. Сначала ord('a') = 97, далее 97 + 10 = 107 и потом chr(107) = 'k'. Затем ord('k') = 107, далее 107 + 250 = 357 и потом chr(357) = 'ť'
* Вывод отличается от программы на C++, потому что в Python функция chr() работает с кодировкой Unicode, поэтому она спокойно принимает большие числа, которые не влезают в 1 байт. Число 357 для нее абсолютно нормально, и она выводит символ ť, а не сбрасывает его до буквы e.
* Получается, что C++ тут ограничен рамками 8-битного типа char и уходит в переполнение, а Python просто берёт код из Unicode.

### Задание 5. **(2)**

*Объясните работу фрагмента программы на С++. В частности, почему* $x+x-x=x$, *но при этом*
$(x\cdot 2)/2\neq x$? *В отчете надо привести вычисления, приводящие к ответу.*
```
unsigned short x = 40000;
unsigned short y = x + x;
unsigned short z = x * 2;
y = y - x;
z = z / 2;
std::cout << y << " " << z << std::endl;
```

* Тип unsigned short занимает 16 бит и может хранить значения от 0 до 65535. 
* Сначала вычисляется y = x + x = 40000 + 40000 = 80000. 80000 не помещается в unsigned short, поэтому происходит переполнение в большую сторону. Чтобы узнать, сколько осталось в переменной после этого сброса, выполняется: 80000 - 65536 = 14464. Получаем y = 14464. 
* Далее y = y - x = 14464 - 40000 = -25536. Так как тип беззнаковый, в нём не может быть минуса. Происходит переполнение в меньшую сторону. Для приведения числа к корректному значению, выполняется: -25536 + 65536 = 40000. Значит, y вернулся к исходному значению 40000.
* Теперь считаем z = x * 2 = 40000 * 2 = 80000. Здесь происходит точно такое же переполнение, как во втором шаге (80000 - 65536 = 14464). Получаем z = 14464. После этого выполняется z = z / 2 = 14464 / 2 = 7232.
* Вывод программы: 40000 7232
* Причина различия в том, что x + x - x = x сработало, потому что сначала произошло переполнение в большую сторону, а последующее вычитание устранило его за счёт переполнения в меньшую сторону: (40000 + 40000) - 40000 = 40000. А при вычислении (x * 2) / 2 переполнение и потеря старшей части числа происходят до деления. Мы делим на 2 уже урезанный остаток 14464, поэтому 7232 не равен исходному x.

### Задание 8 **(2)**

*Найдите результаты вычисления следующих выражений без использования компьютера

* `(1000 & 100) << 10`
* `(1000 >> 4) & 15`
* `~1234 + 1234`

* (1000 & 100) << 10. Перевод числа в двоичную систему: 1000 в десятичной = 1111101000 в двоичной(1000/2, записывается целая часть для следующего шага, а остаток откладываем в сторону. Когда дошли до конца деления, выписываем остатки снизу вверх), тоже самое и с 100 в десятичной = 001100100 в двоичной. Далее выполнение побитовое И (1 & 0 это 0, 0 & 1 это 0, 1 & 1 это 1, 0 & 0 это 0), получаем 0001100000, далее это число переводим в 10ую систему: 0*2^9 + 0*2^8 + 0* 2^7 + 1 * 2^6 + ... + 0 * 2^0 = 2^6 + 2^5 = 64 + 32 = 96. Теперь выполним сдвиг влево на 10 позиций (умножаем 96 на 2 в 10 степени), получаем 96 << 10 = 96 * 1024 = 98304. Ответ: 98304
* (1000 >> 4) & 15. Переведём число 1000 в двоичную систему: 1111101000, далее сдвигаем его вправо на 4 позиции (отбрасываем 4 последние цифры): 1111101000 >> 4 = 00111110. Далее переводим 15 в двоичную систему (показывал выше как делать), получаем 00001111. Теперь выполняем побитовое И(показывал как делать выше), получаем 00001110, это число равно 14 в десятичной системе. Ответ: 14
* ~1234 + 1234. Тут для ~1234 используется математическое правило: ~x = -x - 1, значит ~1234 = -1234 - 1 = -1235, следовательно -1235 + 1234 = -1. Ответ: -1
* (1000 ^ 500) & 63. Перевод 1000 в десятичной = 1111101000 в двоичной, 500 в десятичной = 0111110100 в двоичной. Далее выполняется побитовое исключающее ИЛИ(1 ^ 0 это 1, 0 ^ 1 это 1, 1 ^ 1 это 0, 0 ^ 0 это 0), получаем 1000011100. Так же Переводим 63 в двоичную форму 00111111 и выполняем побитовое И, получаем 0000011100, это двоичное число равно 28 в десятичной системе. Ответ: 28
* (100 << 3) + (100 >> 3). Сначала выполняем левый сдвиг (умножение на 2 в 3ей степени): 100 << 3 = 100 * 8 = 800, потом правый сдвиг (целочисленное деление на 2 в 3ей степени): 100 >> 3 = 100 // 8 = 12. Далее 800 + 12 = 812. Ответ: 812
